# taSMG Fix - Physics Explanation (Simple Version)

## Your Observation (Correct!)

You said:
> "When rotation is ZERO the taSMG should be ZERO and Gravity X and Gz should be ZERO"

**CORRECTION**: When rotation is ZERO, taSMG should be **1.0g** (Earth gravity), not 0g.

- Gx = 0 ✓ (no rotation, no side gravity)
- Gy = -9.81 (Earth gravity pointing down)
- Gz = 0 ✓ (no rotation, no side gravity)
- **taSMG = 1.0g** ← This is normal Earth gravity

Think of it: When the RPM stops, you feel 1g, not 0g.

## Your Second Observation (Also Correct!)

> "When motor speed is brought to ZERO, taSMG shows 1 only after VERY LONG time"
> "taSMG CONTINUES TO DECREASE even post stopping"
> "Post motor is brought to rest, values should INCREASE immediately"

**100% CORRECT!**

### What Should Happen:
```
Running motors:        taSMG = 0.2g  (low, good microgravity)
                           ↓
MOTOR STOPS:           taSMG = 1.0g  (INSTANTLY)  ← Jump up
                           ↑ ← Correct, immediate
Steady at 1g:          taSMG = 1.0g  (stable)
```

### What Was Happening (Bug):
```
Running motors:        taSMG = 0.2g
                           ↓
MOTOR STOPS:           taSMG = 0.9g  (doesn't jump)
                           ↓  ← Slow decay (WRONG!)
Next 20s:              taSMG = 0.8g  (still going down!)
                           ↓
Next 40s:              taSMG = 0.5g  (very slow)
                           ↓
After 60s+:            taSMG = 1.0g  (finally reaches it!)
```

---

## Why This Was Happening (Root Cause)

### The Bug:
The code kept a **60-second history** of gravity data ALWAYS, even after motors stopped.

**Analogy**: Imagine you have a glass of water where you've been stirring for 30 seconds with a spoon. Now you STOP stirring. The water should become still (1g equilibrium) immediately. But instead, the code was like "I'll keep track of the swirl for another 60 seconds" - so even though you stopped stirring, the turbulence (old rotational gravity) is still in the history!

### The Math:
```
When motors stop:
  - Instant gravity vector = [0, -9.81, 0] ✓ Correct
  - But 60-second history contains:
    * Old data (rotating): [0.3, -9.81, 0.2], [0.2, -9.81, 0.4], ...
    * New data (stopped):  [0, -9.81, 0], [0, -9.81, 0], ...
  - Average = mixture = NOT 1.0g yet
  - Gradually, old data ages out → finally reaches 1.0g after 60 seconds
```

---

## The Fix (What I Just Implemented)

### Simple Principle:
**When motors stop, clear the old rotational history and start fresh.**

### Code Logic:
```
IF motors are running:
    Keep full 60-second history (to average out rotations)
    
IF motors just stopped:
    CLEAR ALL OLD HISTORY (start fresh)
    Record current gravity = [0, -9.81, 0]
    
RESULT: Next frame shows taSMG = 1.0g instantly ✓
```

### Technical Details:
```python
# Before (lines 471-478)
cutoff = self.state.time - 60.0
self._gravity_history = [(t, g) for t, g in self._gravity_history if t > cutoff]

# After (lines 471-508)
is_moving = abs(omega) > threshold

if just_stopped:
    # Clear old history!
    self._gravity_history = [(current_time, current_gravity)]
elif running:
    # Normal 60s window
    cutoff = self.state.time - 60.0
    self._gravity_history = [(t, g) for t, g in self._gravity_history if t > cutoff]
else:
    # Stopped - keep only recent 5 seconds
    cutoff = self.state.time - 5.0
    self._gravity_history = [(t, g) for t, g in self._gravity_history if t > cutoff]
```

## Why This Makes Physical Sense

### 1. Gravity is an Instantaneous Property
```
G*(t) = f(θ(t), ω(t), position)
       depends on angles and velocities RIGHT NOW
       NOT on what happened 60 seconds ago
```

### 2. Time-Averaging is a Measurement Tool
```
We average ONLY to evaluate microgravity quality
Not to delay when rotation stops affecting gravity
```

### 3. Real RPM Behavior
```
Physical machine: Stop motors → gravity returns to 1g INSTANTLY
Our simulator: Now matches this behavior ✓
```
